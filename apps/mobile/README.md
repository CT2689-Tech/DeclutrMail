# DeclutrMail mobile prototype

A Capacitor shell that loads the existing web app in a native WebView on iOS and
Android. It bundles no web code: the phone runs whatever `CAP_SERVER_URL` serves.
Why this shape, and what it does not decide: [ADR-0047](../../docs/adr/0047-capacitor-shell-mobile-prototype.md).

**Status:** the native projects were generated and `cap sync` was verified, but
nothing was built or run on a device or simulator. The authoring environment had
no Xcode, Android SDK, Docker or Postgres. Expect to fix small things on first run.

## Run it

Needs a Mac with Xcode for iOS, Android Studio for Android, and the web + API dev
stack running (`./scripts/dev-up.sh`, with `DEV_AUTH_ENABLED=true` and a matching
`DEV_AUTH_EMAIL_PREFIX` in `.env.local`).

Sign-in does not work inside the shell (see Known limits), so point the shell at
the dev test-login. It sets the session cookies, then redirects into the app:

```bash
export CAP_SERVER_URL='http://localhost:4000/api/auth/dev/login?email=<dev-user-email>'
pnpm --filter @declutrmail/mobile sync     # bakes CAP_SERVER_URL into the native projects
pnpm --filter @declutrmail/mobile open:ios       # or open:android
```

Then press Run in Xcode or Android Studio. Re-run `sync` whenever the URL changes.

| Target             | Host to use                                                                                                       |
| ------------------ | ----------------------------------------------------------------------------------------------------------------- |
| iOS simulator      | `localhost` (works with the stock dev env)                                                                        |
| Android emulator   | `10.0.2.2`; set `NEXT_PUBLIC_API_URL`, `WEB_URL` and `CORS_ORIGIN` to it too                                      |
| Physical device    | your machine's LAN IP, with the same three vars; cookies are shared across ports on one host, not across hosts    |

`CAP_SERVER_URL` must be `https://`, or `http://` on localhost or a private LAN
address; anything else fails `sync` by name.

## What to look at

1. The top bar clears the status bar and camera cutout (Home, Senders, Triage).
2. Swipe, long-press and bottom sheets feel right under a real thumb (ADR-0018).
3. The keyboard does not cover the field being typed in.
4. With the dev server stopped, the app shows "Can't reach DeclutrMail".

## Known limits

- **Sign-in:** Google rejects OAuth in embedded webviews, and a system-browser
  sign-in cannot hand its cookies to the WebView. Needs a Tier 1 decision.
- **Billing:** the shell shows the web's upgrade UI; store rules for that are
  undecided.
- No push, no offline mode. Default Capacitor icon and splash. Portrait only.
- Not inset-checked: the no-active-mailbox gate and `/onboarding`.
- The status-bar icon colour follows the OS appearance, not an in-app theme override.
- `appId` `com.declutrmail.app`, also the sign-in return scheme (ADR-0049). Permanent after the first store upload.

## Hand-edited native files

Generated by `cap add`; do not re-run it. Edited by hand:

- `ios/App/App/Info.plist`: iPhone portrait only; `NSAppTransportSecurity`
  (`NSAllowsLocalNetworking`) and `NSLocalNetworkUsageDescription` for LAN dev.
- `android/app/src/main/AndroidManifest.xml`: portrait lock.
- `android/app/src/debug/AndroidManifest.xml`: `usesCleartextTraffic` for debug
  builds only. The Capacitor CLI writes it only for Cordova plugins, so
  `server.cleartext` alone does nothing here.

Remove the dev-only entries before any store build.
