# Private finance reporting activation

The existing daily vendor watchdog optionally writes finance reports to a private GCS bucket. No additional schedule or messaging is introduced. Until activated, the reporter does not run.

1. Provision a dedicated bucket with uniform bucket-level access, enforced public access prevention, and versioning. Restrict readers to company finance/admin identities. Review inherited project IAM as well as bucket IAM. Restrict collector access to config reads and observation/report writes; the reporter itself cannot prove inherited least privilege. Root infrastructure deployment owns provisioning.
2. Privately upload `config/invoices.json` and `config/subscriptions.json`, starting from the examples here. Do not commit financial documents, populated registries or invoices to this repository. Keep original documents in restricted company Drive. Existing dashboard imports must be reconciled and converted; this program does not infer payment dates from statement months or dashboard totals.
3. Each invoice entry requires `vendor`, `documentId`, `scope`, `scopeId`, `currency` (three-letter), `kind` (`invoice`, `statement`, `refund`, or `unclassified` when source kind is unavailable), `issuedOn` (YYYY-MM-DD), `amount` (nonnegative), and `sourceUrl` (HTTPS). Optional `paidOn` must represent verified payment/refund date. Do not import both an invoice and its covering statement as separate charges: choose one authoritative document, retaining its reference. Stable document IDs deduplicate retries; contradictory revisions are rejected for reconciliation.
4. Populate subscription fields only from verified terms. `amount`, `currency`, `frequency`, `scope`, `nextRenewal` stay null when unknown. Annual contracts must retain their annual frequency; do not mislabel them as monthly commitments. Update renewal dates after payments. This registry highlights upcoming commitments; it does not manufacture an all-vendor forecast.
5. Set repository variable `PRIVATE_FINANCE_BUCKET` to the bucket name only, after permissions and initial configs are verified. Existing GCP WIF is used, with no new long-lived key. Run a reviewed workflow dispatch and open the resulting private report as the intended admin account before declaring it ready.

Outputs: append-only content-addressed `observations/YYYY-MM-DD/<sha256>.json`; `reports/YYYY-MM-DD.md`; `reports/latest.md`. Enable versioning to retain historical report/config revisions. Source ledger remains `config/invoices.json`; write it only through the reviewed import process. Report contents never appear in GitHub summaries/artifacts or outgoing messages. Existing operational snapshots continue using existing artifact retention and contain no invoice records.

The report separates imported verified paid totals from vendor usage MTD. It never adds unrelated scopes/currencies together or adds invoices to usage charges. Only provider-specific existing forecasts are displayed. Missing vendor billing integrations, invoices and plan prices remain visible as unknown coverage. Cloud usage export is not a paid invoice. The budget checker separately makes a labeled linear projection of matching GCP usage; it does not change any budget amount or spend control.

The collector additionally requires `storage.buckets.get` and `storage.buckets.getIamPolicy` for privacy verification. Use a reviewed custom bucket-scoped role for these checks plus `storage.objects.get`, `storage.objects.create`, and `storage.objects.delete` (overwriting reports), scoped by prefix where supported. Avoid project-wide Storage Admin. Keep config write permission away from the reporting identity. Immutable observations use generation-match zero and verify identical content on a retry. Root IAM review must check inherited access; public access prevention does not prevent overly broad authenticated project members.

`importInvoiceHistory(history)` converts the existing private dashboard ledger. Month-only issue dates retain an explicit placeholder marker and render as month-only; unknown account identity is marked `legacy-import-unverified-account`. Reconcile that identity before combining imports with a new source. Statements and unclassified source records are shown in history but excluded from paid totals to avoid counting the same invoices twice. Entries with unverified account identity are also excluded from paid totals until reconciled. The generated `reports/latest.html` is a self-contained escaped quick-glance document; open/download through authenticated storage access rather than enabling public hosting. HTML has no scripts or external assets.
