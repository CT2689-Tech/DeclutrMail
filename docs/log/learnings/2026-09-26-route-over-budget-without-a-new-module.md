## 2026-09-26 — A route can go over its bundle budget without gaining a module
**Context:** PR #784 (error copy) failed "Build — Web + bundle budget": /activity and /screener over, /brief and /home heavier, none of them importing anything new.
**Finding:** Diffing each route's module ids and chunk lists against a local build of main (evaluate each chunk's `push()` in a `vm` sandbox, read the module table) showed identical module sets per route. Only the chunk partition differed, from two causes. (1) A new file imported two constants straight from `@declutrmail/shared/contracts`. That contracts module had one importer, `lib/api/actions.ts`, and webpack had scope-hoisted it into that importer. A second importer split it back out, which renamed the concatenated module and reshuffled the shared chunks. (2) With that undone, a 7-line export added to `actions.ts` still flipped a Next `splitChunks` decision (`minSize: 20000`, measured before minification, widest chunk combination first): `actions.ts` and the activity query keys got their own 8-route chunk, where main had inlined them into /home. Four routes loaded one more chunk, +0.6 to +1.1 kB gzipped each, because the budget sums per-chunk gzip. Two things fixed it. Consumers read the code from a local constant typed `typeof UNSUB_MANUAL_REQUIRED_ERROR_CODE`, which is pinned at compile time and adds no runtime import. And each screen inlined its own copy, with a test pinning it equal to the shared helper.
**Rule (provisional):** When a route grows but its imports did not, diff module sets and chunk counts against main before trimming code. Keep new runtime imports of widely shared modules (`actions.ts`, contracts) out of error-copy changes. To pin a wire code without a runtime edge, use `import type` plus `typeof`.
**Distillation trigger:** promote to CLAUDE.md §8 "Performance measurement discipline" if a second budget failure traces to chunk regrouping rather than new code.
**Measurement since:** #806 (2026-09-27) makes the budget measure routes as served (layouts and boundaries included, see docs/log/learnings/2026-09-27-build-manifest-is-not-what-the-browser-loads.md). The numbers above are manifest-based; the diagnosis still holds: compare module sets and chunk counts against a build of main before trimming code.
