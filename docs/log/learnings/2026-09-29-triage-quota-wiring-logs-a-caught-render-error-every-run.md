## 2026-09-29 — `triage-screen.quota-wiring.test.tsx` logs a caught render error on every run, not just the ones CI reported red

**Context:** CI on #808 (Quiet copy) went red on two things at once: a real matcher collision in `home-view.test.tsx` (this PR's own copy change) and what read, from the failing check's summary, as a second crash in `triage-screen.quota-wiring.test.tsx` — a `TypeError: Cannot read properties of undefined (reading 'all')` at `triage-screen.tsx:582` (`compositePreview.data.counts.all`), with no file overlap between that test and this PR's diff. Fixing the matcher and pushing made the whole check go green, which read as "the quota-wiring failure didn't recur — flaky."

**Finding:** Pulling both CI runs' actual `Tests — Web` job logs (`gh run view --job <id> --log`) shows the stderr line is byte-identical in the failing run (f6825ea3) and the passing run (8d245533) — same test (`states the single-row cost on the action sheet`), same stack, same line — and in BOTH runs `triage-screen.quota-wiring.test.tsx` itself reports `✓ (3 tests)`. It never failed an assertion either time. The whole check's `conclusion: failure` on f6825ea3 was fully explained by `home-view.test.tsx`'s one real failure; the quota-wiring stderr was noise alongside it, not a second failure, and "didn't recur" was never true — it recurs every run. The test opens the Archive action sheet, which reads `compositePreview.data.counts.all` on a transient render before the preview query's data has landed; React 19 catches the error, retries, and commits fine, but logs the intermediate throw to stderr regardless. The test's own assertions (via `waitFor`) only check the eventually-settled DOM, so they never observe it.

**Rule (provisional):** A red CI check with two different-looking stack traces in its log isn't necessarily two failures — check each file's own pass/fail line (`✓ file (N tests)` vs `❯ file (N tests | M failed)`) before concluding a second test is implicated, and diff the SAME stderr line across a red run and a green run before calling anything "didn't recur." This one is pre-existing (unrelated to #808) and cosmetic (harmless, doesn't fail anything) — not filed as a fix, logged so the next person who sees this exact stack trace in a CI log doesn't reopen the same investigation from zero.

**Distillation trigger:** promote to CLAUDE.md's "known false-positive/negative traps" (§8) if the same "two stack traces in one red check, only one real failure" shape recurs on another PR.
