## 2026-09-28 — A class sweep matched one word, not the claim, and missed 13 of 17 instances

**PR:** #784 (https://github.com/CT2689-Tech/DeclutrMail/pull/784)
**Caught by:** manual re-check of the class after merging main two days later
**What happened:** The /ct-class sweep for "error copy that states what nothing checked" removed "Your mailbox and decisions are untouched" from four route error pages. A boundary cannot see whether a mutation committed before the render failed, so no such page can know that. The sweep searched for the word "untouched". Thirteen more route error pages made the same claim in other words: "Your settings are unchanged", "Your plan is unchanged", "Nothing in Gmail changed", "Nothing was moved or rescheduled", "Events are still being recorded". Two more promised a remedy nothing checked ("reopening it also works", "come back in a moment"). The account menu's disconnect and deletion errors said "Nothing was deleted", although the deletion can be scheduled before the request fails. `RouteErrorScreen`'s own prop doc asked every page for "One reassuring sentence — what is safe", so the component invited the claim.
**Correct approach:** Enumerate the surface type (every route error page, every onError of a mutation) and read each string for its claim, instead of grepping for the phrase the first instance used. Then fix the contract that invites the claim, not only the strings.
**Rule:** A class sweep enumerates surfaces structurally and reads each one; a keyword grep only seeds the search.
**Enforcement update:** `apps/web/src/app/route-error-copy.test.tsx` renders every route error page and fails on a state claim (starved: a glob that matches nothing fails the count). The `RouteErrorScreen` body doc now forbids the claim. The account menu's two error paths have tests.
