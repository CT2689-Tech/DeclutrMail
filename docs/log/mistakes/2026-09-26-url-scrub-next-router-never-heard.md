## 2026-09-26 — A URL scrub Next's router never heard about, and two tests that could not fail

**PR:** #781 (fix/d108-require-gmail-scope)
**Caught by:** flow-completeness-auditor (the scrub; one always-green assertion) + my own negative control (a second always-green test) + security review (the `?connected=` echo)
**What happened:** Three one-shot result scrubs (Settings, the chrome's connect toast, the new /onboarding carry) called `history.replaceState(window.history.state, …)`. That state carries Next's `__NA` marker, so Next's patched `replaceState` treated each call as its own and never told its router; on a first render the patch is not even installed yet, because Next installs it from an effect in its root, after every child effect. The next `router.refresh()` (any mailbox switch) wrote `?reconnect_result=success#mailbox-<id>` back into the address bar, and a reload replayed "Gmail reconnected." Reproduced live before fixing. Separately, a chrome test asserted a toast was absent after the gated chrome had unmounted its only toast host, so it passed whatever the hook did; my own new `?connected=` test passed with the injection branch put back, because the app body renders before the hook's onboarding wait ends. The `?connected=` branch itself put any URL text in a green success toast, and nothing sends that param. My first `replaceUrl` then built each URL at call time, so two scrubs queued in one tick overwrote each other and a reload replayed the result (delta security review).
**Correct approach:** One helper, `replaceUrl`, waits a microtask, edits the URL as it stands at that moment, and passes `null`, so Next copies its own history state and updates its router, and same-tick edits compose. Verified live: a refresh no longer brings the param back, and Back/Forward stay in the same document. Absence assertions record calls on a spy and first wait for a positive event that proves the code under test ran. The `?connected=` branch is deleted.
**Rule:** In a Next app, never hand `window.history.state` back to `replaceState`; an "X did not happen" assertion must first prove the code that would do X has run.
**Enforcement update:** `replaceUrl` unit tests (deferred, null state, same-tick edits compose), and every new absence test negative-controlled against the old code. None to hooks.
