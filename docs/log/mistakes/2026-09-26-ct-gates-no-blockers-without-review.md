## 2026-09-26 — ct-gates returned NO_BLOCKERS for a diff no gate reviewed
**PR:** #789 (https://github.com/CT2689-Tech/DeclutrMail/pull/789)
**Caught by:** manual review while gating #782: ct-gates on its scripts-and-workflow files returned `gatesRun: []` and `NO_BLOCKERS` in 99 ms. Six rounds of the fix's own self-review found the rest.
**What happened:** ct-gates picks gates by path from the CLAUDE.md §7 table. A diff touching only `scripts/*.mjs`, `*.sh`, `.github/workflows/` or `.husky/` matched no gate, ran zero agents and returned `NO_BLOCKERS`, the verdict a clean review gets. Those are the paths where this repo's watchdogs and guards live. #782 was that shape; its silent-failure review happened only because the agent was launched by hand. The self-review found the same shape at every other step. A gate that declined the diff was never read, so a declined privacy-auditor still gave `NO_BLOCKERS` beside any advisory review. A gate that could not read `git diff <ref>` returned no findings, and so did a clean one. A failed scout returned `NO_DIFF`; given a mistyped ref, the haiku scout ran the corrected one instead and returned its files. A dead refuter left its finding labelled `CONFIRMED`. §9 stop conditions, the watchdog acknowledgment lists and changed files no gate routes (root `package.json`, whose scripts CI runs) never reached the verdict. silent-failure-hunter's route never matched `.tsx`, and its charter ran a bare `git diff`, which lists nothing on a committed branch. The default ref, `origin/main...HEAD`, named whatever branch an agent's checkout held, and so do `@`, an empty side and, on a case-insensitive disk, `head`. A caller's file list was trusted whole, so a file left out of it routed no gate. Gate charters counted as prose. Two §7 gates had no route at all.
**Correct approach:** Give each gate an outcome (reviewed, declined, unreadable, died) and let the verdict read all of them. Only `NO_BLOCKERS` is clean. It needs every must-pass gate to have reviewed, and every changed file that is not prose to have been reviewed by some gate. Accept only input the script can pin down: a range of two named refs. Check what the caller passes against what the diff lists. Make every agent echo the exact command it ran, and check the echo in code; a suffix such as `| head -1` or `2>/dev/null` changes what a command shows. A refuter vote that never arrived is `UNVERIFIED`, not `CONFIRMED`.
**Rule:** A review fan-out must report "not reviewed" at every step where it can happen, in its verdict. That covers the files it selects, the gates that run, what those gates read and the votes it counts (CLAUDE.md §8, "a guard that cannot fail", applied to the gate network itself).
**Enforcement update:** `scripts/ct-gates-workflow.test.mjs` (CI Lint) runs the real workflow body against stubbed runtime hooks and pins every verdict. Each behaviour was reverted and turned its test red. Main fails 21 of the 23 tests. The stubs follow the runtime, not the reference: a zero-agent probe showed `pipeline()` ends an item when a stage returns null, which the reference does not say.
