## 2026-09-26 — The tab-recount fix shipped five defects its own tests did not see
**PR:** #786 (https://github.com/CT2689-Tech/DeclutrMail/pull/786)
**Caught by:** adversarial review of #786 at c91f7e82 (orchestrator-requested)
**What happened:** (1) The sweep's re-score request publishes `triage.score_run_completed`, which wakes the Autopilot apply sweep, and it was sent for any active+ready mailbox — including one whose owner had an account or data deletion in its undo window (D232) or whose grant needed reconnecting. The Autopilot action worker gates only on entitlement and quiet, so the new producer was the only place those states could be checked. (2) The importance-protection release withdrew protections earned on mail Gmail itself labelled Primary whenever the sender lost its strict majority (a tie with Updates), and every release was silent. (3) The journey report flagged `LLM_OFF` on a template-only re-score, a model outage alarm raised by policy. (4) All four steps ran in one lock hold (~20s on the largest dev mailbox), so a user's Archive queued behind the whole sweep. (5) The initial-sync rebuild rewrote `gmail_category` without marking the moved senders' decisions, so the same-verdict reuse kept "…your Primary inbox" after a rescan — the sweep's recount had the mark, its sibling writer did not.
**Correct approach:** Gate the re-score on the consumer's preconditions (active, ready, working grant, no deletion pending) at the producer; withdraw the Primary half of an importance protection only when the sender has no Primary-labelled mail at all, and return, count and log every net release by prior reason, in all three callers, after the commit; report `explanationsNotRequested` and exclude it from `LLM_OFF`; shorter lock holds, split only where no lock waiter can act on the state between them (timeseries alone; the recount, its marks and protection together — see the 2026-09-27 entry); `markDecisionsStale` called by every writer of the tab.
**Rule:** When a new write wakes a consumer that acts in Gmail, list the states in which that consumer must not act and gate the producer on them — do not assume the consumer checks them.
**Enforcement update:** tests for each (deletion-pending, data-deletion and reconnect mailboxes are recounted but not re-scored; tie keeps an earned protection; release reported with prior reason; a correction is not a release; a protection failure rolls the recount back with it; lock failure named `lock`; payload cap largest-first; rescan marks moved senders; journey not `LLM_OFF`; new counters reach `worker.succeeded`), each verified red against a negative control.
