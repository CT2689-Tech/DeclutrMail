## 2026-09-27 — Splitting the sweep's lock hold let an Autopilot action run before the protection the recount implied
**PR:** #786 (https://github.com/CT2689-Tech/DeclutrMail/pull/786)
**Caught by:** architecture-guardian (read-only retry) on the review follow-up f7054565
**What happened:** To stop a user's Archive queueing behind a hold of ~20s (per-step dev timings at high machine load, summed), the follow-up split the sender-index sweep's single lock hold into three: timeseries, then the Gmail tab recount (with its decision marks), then auto-protection. The context-moving review listed the lock-free readers (Autopilot apply, label actions, the per-push protection pass) and found them safe, but it did not list the lock WAITERS. The Autopilot action worker takes the same mailbox lock for each match and checks only `is_protected`. An action queued during the recount hold gets the lock before the sweep's next request, so it runs after a sender's tab has moved into Primary and before the importance protection that tab implies exists. It would then send an approved unsubscribe that cannot be undone. If the protection hold failed, that state lasted until the next sweep, up to 24h. Every test was green; the interleaving had no test.
**Correct approach:** Split a hold only where nothing that can act runs on the state between the pieces. The recount, its marks and auto-protection are one transaction (a transaction reads its own writes, so no commit is needed between them), and timeseries, which feeds no safety state, keeps its own hold. The re-score eligibility read moved after the holds too, so a deletion requested while the sweep waited still stops the re-score.
**Rule:** Before splitting a lock hold, list every waiter on that lock and what it acts on, not only the lock-free readers — a waiter runs exactly in the gap you create.
**Enforcement update:** a sweep test snapshots the state a lock waiter would see after each hold and fails if any snapshot has a sender moved into Primary but not yet protected (red with the hold re-split); a protection failure now rolls the recount back (tested); a mid-sweep deletion test (red with eligibility read up front).
