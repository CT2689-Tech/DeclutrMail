## 2026-09-26 — "No tab label" was stored as Primary, so senders were kept "because Gmail puts them in your Primary inbox"
**PR:** branch `claude/trusting-pascal-e2012d` (Gmail tab truth, migration 0079)
**Caught by:** production trace by the founder (one production mailbox, 2026-09-25), then `/ct-class`
**What happened:** Both sync workers mapped a message with no `CATEGORY_*` label to `primary` — the justification was a code comment ("the message sits in Gmail's Primary tab"), never a check — counted those messages as Primary votes, and broke ties toward Primary. Cascade rule 3 then kept the sender at 95% before any volume, read-rate or unsubscribe check, and both the template and the Haiku prompt stated Primary as fact. On that mailbox 30,443 of 38,259 inbound messages had no tab label, 1,552 of 2,554 Keep-95% senders came only from the default, and the user overrode the engine on 23 of 23 actions (one bulk Delete removed 12 "Keep" senders, 8,790 emails). The same stored value let the importance rule auto-protect guessed-Primary senders, kept the Senders row from leading with Unsubscribe, and went into the data export. Present since the first sync worker (PR #17, 2026-05-22); the tests that touched it seeded unlabelled mail and expected the Primary outcome.
**Correct approach:** Store `unknown` when no labelled mail backs a tab; a sender's tab is the one more than half of its LABELLED mail carries (a tie is not "Primary"). Correct existing rows through the nightly sweep that keeps them correct, before auto-protection reads them, and expire the changed senders' decisions so a same-verdict re-score cannot reuse the old sentence.
**Rule:** A provider field that can be absent needs its own "unknown" value before anything reads it — a default must never stand in for an observation.
**Enforcement update:** tests (each negative-controlled against the old code): unlabelled sender → `unknown` in initial and incremental sync, unlabelled votes no longer outvote a real label, tie → `unknown`, importance does not protect an unlabelled sender, the sweep corrects the tab before protection and requests one re-score for exactly the changed senders, and a same-verdict re-score no longer keeps the Primary sentence. No hook: "absent means unknown" needs a reading, not a match.
