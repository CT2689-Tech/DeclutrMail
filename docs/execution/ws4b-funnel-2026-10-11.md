## Decisions

- `dm_attr` is set once, for 30 days, first-party, and is not overwritten.
  It is copied onto a new user at signup only.
- `hd` present classifies `signin_provider` as `workspace`, including a
  gmail.com address. Otherwise `@gmail.com` and `@googlemail.com` are
  `gmail`. Anything else is omitted. The domain is not stored.
- `SYNC_FAILED_NOTICE_WHILE_RETRYING` is false. The retrying sentence is
  in the copy module and is not rendered.
- `CONNECTION_TERM` is read from the screen-decisions stub (`Gmail account`,
  plural by adding `s`). `BRIEF_NAME` is `Daily Brief`.
- Email clicks are `POST /api/v1/analytics/email-click`.
- Product-event retention is 13 months in `OpsRetentionWorker`.
- The funnel SQL allowance is `TIER_MANIFEST.free.cleanupActionsPerMonth`
  (50 on this stub).
- Vercel Analytics is skipped. The marketing layout is WS3's.

## Cross-WS

- `EmailClickRecorder` is mounted in `MailboxLinkBoundary`, outside the
  children the resolver withholds, so `mailbox` is still on the URL.
  WS2 must not mount a second copy or the click is counted twice.
- WS3 adds the `/cookies` row for `dm_attr`. On preview hosts,
  `withSignupRef` should also append `dm_attr`, because the cookie is
  host-only there and the API will not see it.
- `purchase_confirmed` and `free_cap_hit` pass the earliest workspace
  user's id. The lookup selects that id only. `checkout_created`
  already passed `principal.userId`. No payment state changes.

## Production steps

- `0086_product_events.sql` is additive. Apply it with the normal
  migration path. Do not run it from a laptop against production.
