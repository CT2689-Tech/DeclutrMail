## Acceptance rules for future additions

1. Place a new task inside the existing five navigation groups before considering another global destination. Long reading/settings pages get local contents; collections get filters with honest server/loaded scope.
2. Choose the existing wide workbench, focused decision, or reading/settings composition. Use shared type, controls, semantic colors, focus states and spacing rather than inventing another page theme.
3. State inbox/workspace scope and period beside the heading or controls. Keep current-mail actions, future unsubscribe requests and automatic rules distinct; use canonical action labels.
4. Specify ready, loading, empty, filtered-empty, error/retry, pending and restricted states as applicable. Preserve route identity and a valid next action; missing data is not zero.
5. Review the same scenario in the actual app and its fixture at matching viewport/theme. Preserve the list/inspector relationship on desktop, usable mobile detail, bulk counts and historical-mail controls.
6. Keep public explanations and the demo aligned with production behavior. Record recommendation→implementation→test/browser evidence before claiming completion.
