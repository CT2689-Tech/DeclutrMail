## Remaining work a user would actually notice

Ordered by product impact.

1. **D79 — Later/Snooze does the opposite of what it promises.** It archives existing
   mail by default and never intercepts future arrivals, so a snoozed sender keeps
   landing in the inbox. The shipped contract text asserts "Future email is unchanged."
   Highest-trust-damage item in the range. **L**
2. **D93/D94/D96 — Quiet Mode holds no mail, but says it does.** The screen renders a
   held count that is actually an Autopilot _action_ count. Either build real holding
   (hold rule + release worker + Held label) or relabel the surface honestly. This is
   the documented "UI truth bug" class. **L** (or **S** for the honest-copy fix)
3. **D66 + D64 — the Brief is uncontrollable.** Weekend opt-in has a worker, API and
   tests but zero UI; delivery time is hardcoded 8am at every layer. A paying user
   cannot change their daily digest at all. **S** for the weekend toggle, **M** for time.
4. **D57 + D56 — Activity rows don't open and can't be filtered by status/undo.** No
   "why this happened", no operation id, no undo detail — the audit trail is a flat list. **M**
5. **D26 — the Senders list shows no reasoning at all**, and the specced popover form
   exists nowhere. **M**
6. **D82 — snooze presets are on the wrong surface.** The actual snooze triggers give a
   bare datetime box defaulting to +7 days; the nice preset sheet only appears when
   _rescheduling_ something already snoozed. **S**
7. **D106 — no skip affordance on onboarding steps 1–3**, so a user who wants out of
   Promise/Connect/Sync is stuck. **S–M**
8. **D53 — senders search has no trigram index**; every keystroke seq-scans. Fine today,
   bites on a large mailbox. **S**
9. **D51/D50/D54 — Senders filter drawer, row accordion and mobile long-press select.**
   A different (arguably better) chip model shipped; the gap is real but the surface works. **M** each
10. **D38 — the verb tour never renders for the "protect important senders" onboarding
    branch**, so ~⅓ of new users never learn K/A/U/L/D in context. **S**
11. **D113 — no welcome email** after onboarding completes. **M**
12. **D109 — no browser push** ("Notify me" when sync finishes). **M**

Not user-visible but worth a decision: **D27** is plan drift, not missing work — the
shipped empty state deliberately asserts "there is no daily obligation," contradicting
D27's locked daily-ritual cadence. That needs a founder ruling (supersede D27, or treat
the copy as a regression), not an implementation ticket. **D111**'s devPreference column
is dead weight — build it or drop it.
