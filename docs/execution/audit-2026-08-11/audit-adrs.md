## 7. Method notes (anti-blind-guard)

Checks that were **not** vacuous — each returned a result that could have gone the other way: migration rollback pairing (enumerated 54 pairs, would have named any gap); `@nestjs` absence (positive control on the same tree returned 99 files and `bullmq` hits); `messages.delete` (grep hit only prohibition comments, proving the search space was populated); violet retirement (**returned hits**); ADR-0031 drift grep (23 populated files classified individually, and the ADR's own removed-literal comment proves the pattern is findable); vendor watchdog exit code (**executed both directions** — forced breach → 1, no secrets → 0).

Checks that were **weak or impossible**, reported as such rather than as passes: ADR-0011 (no mechanical check exists that could fail → **UNKNOWN**, not PASS); ADR-0022 live infra (needs console access → **UNKNOWN**); attachment-data absence (keyword search only — it proves no column is _named_ for attachments, not that attachment bytes are absent from a differently-named column; closed upstream by `format=metadata` being the only call shape); ADR-0014b "never decremented" (grepped assignment shapes, so an unanticipated decrement form could hide).

One check where the mechanical rule gives the **wrong** answer: ADR-0028's "the payload governs, the column never does". `job.reach` **is** read at `label-action.worker.ts:737` — but only inside the damaged-payload branch, where its sole effect is to strip the `+INBOX` re-add. A grep-only verdict returns a false VIOLATED.
