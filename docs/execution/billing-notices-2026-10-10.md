# DeclutrMail billing lifecycle notices

The founder approved provider payment receipts/invoices plus DeclutrMail notices for cancellation, pause, app access deadlines and complimentary grant expiry on October 10. The root agent owns Billing transition/outbox emission, typed event contracts, notification templates, email worker validation and worker composition. This branch depends on deletion #918 and copy #919; refund policy integration is coordinated by the same owner. No other session implements these files.

Notices describe verified app access and actions, never a payment receipt or unverified provider outcome. Emit logical transitions transactionally and deduplicate local request/provider echoes. Recheck current recipient, suppression, subscription/deadline/grant revision and resolved access at delivery; canceled, superseded or deleted state skips stale messages. New grants/extensions/revocations must not receive old expiry notices. Complimentary floors remain authoritative. No Gmail content, raw provider payload, checkout signature or payment details in event/email payloads. Historic billing state is not backfilled into emails.

Use the existing outbox, Resend suppression/idempotency and reply-to support path. Provider settings must be read before enabling overlapping lifecycle notices; sandbox catalog/destination inspection found no active route, which is webhook evidence only and not billing-email configuration proof. Synthetic/mocked email verification cannot be reported as real delivery. No real recipient test email is authorized.

Implementation, tests, template rendering and independent review are complete. Rollout and actual email delivery remain unverified. Billing prices, payment receipts, automatic provider financial writes, grant duration and inbox policy are outside this notice change.

Implemented: strict metadata-only billing.lifecycle_changed events; deterministic UUID publication through the existing validated outbox; canonical local cancel/provider pause/deadline detection; bounded future/recent grant expiry enrollment; semantic revision checks over exact expiry, tier and revocation; current membership/address resolution and fresh rendering in the existing EmailSendWorker. Delayed notices are valid only for 24 hours, shorter than the existing 7-day completed-job retention, so historical redelivery cannot create a fresh send. No historical subscription backfill. The grant scan warns if its ten keyset pages are exhausted.

Runtime stays off unless BILLING_APP_NOTICES_ENABLED=true and BILLING_APP_NOTICES_START_AT is an explicit valid enrollment instant. Producers must be enabled only after the notice-capable worker is serving; older routers ACK unknown topics. This is rollout ordering, not a new billing-policy choice. A disabled current consumer throws rather than silently acknowledging a published notice.

Paddle Billing's official customer-email inventory (https://www.paddle.com/help/manage/your-customers/which-emails-will-customers-receive-on-paddle-billing) confirms provider cancellation, pause, receipt and refund emails. App templates therefore explain app access/grant floors and route to Billing/support; they do not reproduce receipts or claim provider refunds/billing stops. Sandbox dashboard account settings did not expose an email-disable switch; no provider email setting was changed. Live account-specific provider settings and actual email delivery remain unverified.

## Approved upgrade-refund policy copy

The public refund policy now distinguishes a full purchase/renewal refund from an upgrade-only Paddle refund. Only the upgrade is reversed, preserving the previously paid plan's remaining access and original renewal terms; ambiguous restoration directs the user to support with verified access. Ordinary refunds retain their provider-confirmation or bounded refund-review deadline behavior. This changes no guarantee window, fair-use rule or payment behavior.

Independent copy review caught two overclaims before publication: provider approval is not the only access cutoff, and Billing does not currently display the refund-review deadline as a date. The final copy includes the existing deadline and makes no claim that a date is displayed. The existing 30 legal-page tests, web typecheck, touched-file lint, production build and all 51 bundle budgets pass. The built-in browser verified the rendered Section 3, with proof saved as billing-upgrade-refund-policy.jpg outside the repository. This copy depends on #924 and is held with this notice PR until the isolated Paddle sandbox rehearsal establishes the approved refund behavior.
