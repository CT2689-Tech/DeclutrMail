# Upgrade-only refund reversal

The founder approved reversing only an upgrade when its full charge is refunded on October 10. This work depends on deletion PR #918 and copy PR #919. The root agent owns the Billing adapter/interface, durable intent records, webhook/reconciliation classification, synthetic tests and sandbox rehearsal. No other session implements these files. Existing checkout SDK, ordinary subscription refunds, chargebacks, grants and prices retain their separate policies.

Before an immediate Paddle upgrade, capture fresh provider evidence for the exact prior price, tier/cycle, paid-through period, renewal date, cancellation schedule and discount, then commit a metadata-only intent under the subscription lock. Bind the transaction during the original operation through a server-signed intent, a frozen discovery window and complete bounded pagination across every transaction status. Verify one target debit and only an allowed prior-plan prorated credit. Persist one transaction per intent and one intent per transaction. Custom data alone is insufficient because Paddle copies it onto later transactions; a later refund cannot enroll an unbound charge. An ambiguous outbound outcome retains its barrier and cannot be retried as another charge.

Only a provider-approved full refund of that exact upgrade transaction can restore the previous plan. Pending/rejected adjustments leave access unchanged. Reconciliation must use the same transaction classification, so it cannot subsequently terminate a restored base plan. Chargebacks take precedence. Unknown transaction origin, missing prior evidence, an intervening renewal/plan change, expired prior access, cancellation/pause, or an unconfirmed restoration requires support; never resurrect a terminal subscription or create another charge.

Restoration uses the existing server adapter, `do_not_bill`, preview and fresh readback. The automated path uses one item request only when preview proves the original renewal date is retained. Cycle-changing/date repairs remain a support path until their separate write protocol is rehearsed. Project only confirmed prior price and original renewal/paid-through facts through Billing's canonical entitlement writer. Recompute complimentary floors and preserve metering.

Release requires meaningful negative controls, independent review and a sandbox purchase/webhook/upgrade/refund rehearsal covering monthly and cycle-changing upgrades, duplicate/reordered events, cancellation/chargeback precedence, unknown outcomes and no extra charge. Automatic provider restoration is gated off by default through BILLING_UPGRADE_REFUND_RESTORE_ENABLED. New-policy refund classification and durable support barriers are implemented, with 21 real-policy regressions and 92 adapter tests passing; release evidence remains pending. Live writes and low-value cutover payment/refund retain the explicit live confirmation boundary in AGENTS.md.

Independent review found and verified corrections for strict full-charge evidence versus ordinary refunds, complete pagination with frozen filters, immutable classification audit records, refund-specific review barriers, and a second cancellation during uncancel. Current targeted verification: 113 policy/adapter tests, 150 canonical webhook/service regressions, 128 Billing UI tests, and full repository typecheck. Touched-file lint and format checks passed. Removing the refund-specific barrier key caused the delayed-confirmation regression to fail; final source was restored. Provider financial rehearsal remains unperformed and automatic restoration stays disabled by default.

The isolated rehearsal workflow runs only from main in the existing Sandbox environment with its sandbox key and a disposable Postgres service. It creates a separately owned temporary webhook destination and client token, serves the existing checkout launcher, and authenticates every operator state/action with a per-run private capability. The public receiver requires the existing raw Paddle signature verification before any fixture write. No production database, Gmail or Resend is used. Boundary refusal tests and a credential-free browser bundle build pass.

Each fixture has one charged upgrade and one upgrade-only refund attempt; uncertain results cannot be retried. Proof requires the exact canonical restoration record, prior price and original renewal, complete all-status transaction identity comparison with no new artifact, verified webhook replay deduplication, and the exact cycle-change support hold. Shutdown revokes its capabilities, drains handler work, discovers only signed own fixtures and verifies subscriptions stopped by fresh provider reads. Unknown creation or cleanup outcomes fail the run. Financial rehearsal remains unperformed as of this commit.

Worker restoration is explicitly prohibited at startup. Existing worker bindings contain a provider API key but no attribution HMAC secret; upgrade origin remains classified separately from ordinary refunds, so it can hold unverified evidence without ending the base plan. Automatic restoration may be enabled only on the API after sandbox and approved cutover, preserving the API-only signing/client secret boundary. An explicit missing-HMAC adapter regression and worker configuration guard cover this seam.

Historical required-browser failures are preserved: PR CI38080068002 and Founding main CI38080555234 raced the anonymous recovery destination against the dev-login page's own401 redirect, producing ERR_ABORTED or returnTo=/home. Saved trace and page state show that test setup conflict. The anonymous fixture now skips dev login and starts on a blank page; all full destination assertions remain unchanged. No retry, suppression, or product assertion was weakened.
