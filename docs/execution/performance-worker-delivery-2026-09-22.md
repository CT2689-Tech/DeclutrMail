## Quota and correctness boundaries

Gmail minimal-label reads use the same messages.get quota as metadata. Stable bursts therefore use two additional profile requests, rather than a label request for every message. If Gmail history changes during prefetch, one extra label request per prefetched, existing message is necessary to preserve current state. The adapter currently conservatively charges its existing fixed units per call, including profile; that quota accounting was not loosened. Already consumed reservations are not refunded on cancellation, preventing accidental overspend.

The local mailbox lock cannot serialize user actions performed directly in Gmail, which was already true. Profile bracketing protects the newly introduced outside-lock read window; inside-lock label refresh preserves the existing serialization with DeclutrMail actions. Counter/cursor idempotency and sender-scoped recomputation remain intact.

## Cancellation limits

This is cooperative cancellation and cleanup ownership, not a hard global kill of arbitrary third-party code. Already-running queries are drained; sender reconciliation SQL has SET LOCAL deadlines. Other workers/DB queries that do not consume the signal are not newly guaranteed a wall-clock ceiling. OAuth token acquisition and Redis command execution can still depend on their existing transport behavior; quota sleeping and touched Gmail HTTP reads now accept cancellation. No unsafe session SET, global role timeout, forced process exit or release of a live mailbox lock was introduced.
